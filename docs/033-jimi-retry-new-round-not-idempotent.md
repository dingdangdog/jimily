# 033 — Jimi「重试」恢复为「新的一轮」而非复用 clientRequestId

## 变更时间

2026-03-30

## 原因

产品约定：用户消息旁的 **「重试」** 表示用**相同正文**再发起**一次新的对话轮次**（例如隔日再记一笔相同描述），与在输入框重新发送同句等价，**必须允许再次记账**。

032 中让「重试」复用历史消息上的 `clientRequestId` 会命中服务端幂等，导致无法达成上述需求，已撤销该行为。

## 当前行为

- **发送 / 重试**：每次均生成**新的** `clientRequestId` 调用 `api/entry/ai/chat`。
- **服务端**：仍对**同一** `clientRequestId`（同用户内存键 + 库内会话唯一）做并发合并与短时缓存，以及库内「同会话同 id」的防重复插入；该路径主要覆盖 **API/代理层用相同 id 重试**，**不由** Jimi「重试」按钮触发。

## 文案

- 等待中的提示区分：**勿连点发送**；**「重试」** 为独立能力，会再发**新的一轮**。
